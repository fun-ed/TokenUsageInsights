# Fork spec invariants

- Canonical spec: `docs/fork-spec.md`. It overrides upstream `doggy8088/TokenUsageInsights` code/docs and older notes. Upstream = code source only.
- Platforms: macOS + Linux only. No CI/CD; releases manual. `.github/workflows/` stays absent/empty.
- Since v10.0.8 the code has zero Windows branches (no `cfg(windows)`, `cfg!(windows)`, `target_os = "windows"`, PowerShell runner, ZIP assets, `.exe` naming, `%USERPROFILE%` expansion, WSL `cmd.exe`, backslash path normalization) and no `zip` crate. Non-unix builds are unsupported; do not add fallbacks for them.
- Updater `GITHUB_OWNER = "fun-ed"`; `update` and background auto-update query only fork releases (`.tar.gz` assets + `SHA256SUMS`).
- Upstream sync: remote diff review → port one reviewable commit per item (`git cherry-pick -n`, resolve, commit) → apply spec §4 removal checklist (CI/CD, `*.ps1/*.bat/*.cmd`, Windows installer/service runner, Windows cfg branches, Windows path/URI handling, Windows docs, extra README locales, upstream download URLs, upstream `1.x.y` versions, upstream CHANGELOG and `tasks/` notes) → run §4.3 checks. Never merge/rebase upstream wholesale. If upstream tags are fetched locally for cherry-pick, delete the local `v1.*` tags afterwards so they are never pushed.
- Upstream sync baseline: reviewed through upstream v1.3.2 as of v10.0.19 (spec §2.8). Ported 457d8d0, 42fd4f3, 5037a1f, e9fd923, 82b83c8, 9a72368, 547f8c7; skipped 7d9a170 (build date would replace the fork's browser-local sidebar date from v10.0.7) and upstream release bumps. Start the next remote comparison at v1.3.2. Earlier baselines (v1.2.0, v1.2.1) are historical.
- Background sync (v10.0.19): newest-first, cooperative cancel (`*_with_cancel`), preloaded `load_sync_state_for_prefix`, WAL, `bump_sync_data_revision()` after each committed file; `/api/version` exposes `syncing`, `initial_sync_completed`, `data_revision`. Fork Claude sync keeps per-source `source_kind` keys, mtime-nanos change detection and error propagation; OMP keeps per-source `state_prefix`.
- Antigravity native import (v10.0.19): `brain/<id>/.system_generated/logs/transcript_full.jsonl` + read-only `conversations/<id>.db` for model and workspace URI (CWD). Legacy `usage/` hooks still import; native rows replace hook rows for the same session. `file_uri_path` accepts only local `file://` paths (no drive letter/UNC). Fork `insert_usage_entries` takes explicit `source_kind`/`source_dir_key` params.
- Overview (`all`, spec §2.3): fork-first merge of upstream `4a5c3da`. `all` is not in `assistantMeta`; frontend uses `isAllAssistantsScope()` / `getAssistantMeta('all')` (fork `overview.svg`, name 總覽), backend uses `is_supported_report_assistant()`. Share table per view ranks by total tokens; monthly/yearly stacked charts read each breakdown bucket's `agents`; setup-info and manual sync accept `all`; import/export/history/rollback/session detail stay single-assistant. Data-source list shows each Claude profile from `claude_sources`.
- Claude multi-profile: `get_claude_sources()` scans `~/.claude` + `~/.claude-profiles/<name>/` with `projects/` on every sync; `source_kind` `claude-default` / `claude-profile:<name>`; UI badge via `getSessionSourceBadge()`. `CLAUDE_DIR` set ⇒ profiles skipped; service must not set it.
- OMP multi-profile: `get_omp_sources()` = `~/.omp` (`omp-session`, NULL `source_dir_key`) + `~/.omp/profiles/<name>/` (`omp-profile:<name>` + hex dir key). `OMP_DIR` set ⇒ profiles skipped. Shared check `omp::is_omp_source_kind()`.
- `config.yaml` `additional_sources.<tool>` (spec §2.6, `src/config.rs`) extends, never replaces, defaults/profiles; reloaded on every sync. Claude/OMP extra roots join `claude_sources_with()`/`omp_sources_with()` as independent sources `claude-source:<hex>` / `omp-source:<hex>` (hex = canonical absolute path bytes; badge shows last two path components). Other tools keep the primary `source_kind` and use `<tool>:source:<hex>:` sync-state prefixes via `source_state_prefix()`; the primary root keeps its legacy cursor. Paths expand only `~`/`$HOME`; no Windows expansion.
- Auto import = resident server. `scripts/install.sh --service` → launchd `com.tokenusageinsights` (macOS) / systemd user service (Linux); HOST default `0.0.0.0`. Never run `install.sh` inside the install dir (it `rm -rf`s `static/` etc. before copying).
- Only surviving transcripts import; Claude default `cleanupPeriodDays` 30 deletes them; `history.jsonl` has no token usage. Keep 365+ in every Claude root. Known gap: 2026-01..2026-07 Claude transcripts are gone.

- 目前發行與來源標籤、隔離安裝及常駐服務的分別驗證狀態見 `mem:manual_release_and_readme`。舊版本 session 記憶與 KB 筆記只保留歷史證據，不能據以推定目前狀態。

- Claude subagent identities and parser migrations must remain source-scoped, including NULL default source keys. Reset existing-source cursors transactionally, reparse surviving transcripts, preserve historical usage whose transcript is gone, and never mark a failed migration complete.
- Streamed usage selection must keep model/effort from the same selected event. Reasoning can span streamed/tool events but resets on a new prompt. Orphan subagents retain their own badge and metadata fallback.
- Session-title display (v10.0.20, spec §2.9): `formatSessionNameDisplay(name, cwd)` hides complete `<pasted_content ...>` opening/closing markers but retains their contents, including an opening marker without a closing marker. A title beginning with `<system-reminder>` displays as `Magpie` only when CWD contains `magpie` case-insensitively. Applies to list/chart/drawer/model-session and parent-name UI. No transcript/DB title migration, harness reassignment, cost changes, or cross-harness deduplication.
